# Описание проекта и демонстрационного приложения (`demo`)

Этот документ описывает архитектуру, устройство и порядок работы всего репозитория **`_lib_crazy74_git`** с акцентом на демонстрационное веб-приложение (`/demo`), показывающее практическое применение серверной (`lib-php`) и клиентской (`lib-js`) библиотек.

---

## 1. Общий обзор архитектуры проекта

Репозиторий представляет собой законченную экосистему, состоящую из трех основных блоков:

1. **`lib-php/`** — серверная инфраструктурная библиотека общего назначения (ядро, служебные классы, работа с БД, шаблонизатор Twig, REST API и интеграция с AI).
2. **`lib-js/`** — клиентская библиотека на ванильном JavaScript и jQuery-плагинах, отвечающая за интерфейсную логику, форматирование, AJAX и локализацию.
3. **`demo/`** — демонстрационное веб-приложение, выступающее в роли эталонной реализации архитектуры веб-сервиса на базе `lib-php` и `lib-js`.

## 2. Устройство демонстрационного приложения (`demo`)

Демонстрационное приложение построено по схеме **Single Point of Entry (Единая точка входа)** с маршрутизацией через контроллеры страниц и обработчик AJAX-запросов.

### 2.1. Точка входа (`index.php`)

Файл `demo/index.php` выполняет следующую последовательность шагов:
1. Подключает главное ядро библиотеки `lib-php/common.php`.
2. Регистрирует автозагрузчик классов демо-приложения (`demo/classes/` и `demo/page/`).
3. Инициализирует конфигурацию окружения (подгрузка локальных настроек из `/debug/`).
4. Проверяет тип запроса:
   - Если запрос является AJAX (`App::is_ajax()`), управление передается в диспетчер `App::ajax()`.
   - Если запрос обычный HTTP GET, происходит определение текущей страницы и вызов соответствующего контроллера из директории `demo/page/`.

### 2.2. Архитектура контроллеров и рендеринг (`page/` и `twig/`)

Все контроллеры страниц находятся в директории `demo/page/` и наследуются от абстрактного класса `TwigPage`.

- **Контроллер страницы (`TwigPage`)**:
  - Отвечает за подготовку контекста данных, сборку метатегов (title, description), подключение необходимых CSS/JS ресурсов и вызов шаблонизатора.
  - Поддерживает интеграцию каскадной локализации: автоматически передает текущий языковой словарь в Twig-контекст.
- **Шаблоны (`demo/twig/`)**:
  - Построены на базе адаптивного форка Twig 1.15.1.
  - Базовый шаблон (`layout.html.twig`) задает каркас HTML-документа, подключает стили, скрипты `lib.crazy74.js` и `lib.crazy74.jquery.js`, а также инициализирует языковое окружение на клиенте.
  - Дочерние шаблоны страниц расширяют блоки базового каркаса (`content`, `scripts`, `styles`).

### 2.3. Диспетчеризация AJAX (`App::ajax()`)

Обработка асинхронных запросов централизована в `demo/classes/App.php`:
- Принимает параметр действия (`action`).
- Выполняет валидацию входных данных через объект `request`.
- Маршрутизирует вызов в соответствующий сервисный метод или контроллер.
- Возвращает унифицированный JSON-ответ с полями статуса (`status`), данных (`data`), ошибок (`errors`) и времени выполнения (`worktime`).

### 2.4. Интеграция с искусственным интеллектом (`AIGemini` и `AIOpenRouter`)

Классы `demo/classes/AIGemini.php` и `demo/classes/AIOpenRouter.php` демонстрируют работу с LLM REST API:
- Наследуют или используют общие классы библиотеки `lib-php/AI/`.
- Выполняют формирование системных и пользовательских промптов, отправку запросов и парсинг структурированных ответов.
- Поддерживают безопасную загрузку API-ключей из локальных файлов конфигурации (`debug/`).

## 3. Взаимодействие компонентов

1. **Серверный слой**: `demo/index.php` -> `lib-php/common.php` -> `App::startup()` -> вызов контроллера `page/*.php` -> рендеринг Twig-шаблона.
2. **Клиентский слой**: Загруженный в браузере HTML инициализирует скрипты `lib.crazy74.js` и `lib.crazy74.jquery.js`.
3. **Асинхронный обмен**: Клиент отправляет AJAX-запрос -> `App::ajax()` -> обработка в `demo/classes/` -> отправка JSON-ответа -> обновление DOM на клиенте утилитами `lib.crazy74.js`.

---

## 4. Развертывание и запуск

1. **Требования к серверу**:
   - PHP 8.2 или выше (с включенными расширениями `mysqli`, `json`, `curl`, `mbstring`).
   - Веб-сервер Nginx или Apache с поддержкой перенаправления на `index.php`.
2. **Настройка конфигурации**:
   - Скопировать шаблоны конфигурации из `debug/` и указать локальные параметры подключения к БД MySQL/MariaDB и API-ключи AI-сервисов.
3. **Запуск**:
   - Направить root директорию виртуального хоста на корневую папку репозитория.
